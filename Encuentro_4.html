Importación de Archivos Comprimidos

Las funciones read_* de readr (en tidyverse) detectan y descomprimen automáticamente en memoria los archivos al leerlos, sin necesidad de instalar paquetes adicionales ni desempacar en el disco duro.

Formatos soportados de forma nativa:

  • Gzip (.gz): El estándar más habitual para comprimir datasets extensos.
  • Bzip2 (.bz2): Ofrece mayor tasa de compresión.
  • XZ (.xz): Alta compresión usada en servidores y repositorios.
  • ZIP (.zip): Funciona directamente si el archivo contiene un único texto.

Casos especiales (Archivos ZIP):

# Si el .zip contiene un solo archivo:
library(tidyverse)
datos_zip <- read_csv("reporte_anual.zip")

# Si el .zip contiene múltiples archivos:
datos_zip_sub <- read_csv(
  unz("archivos.zip", "tabla_especifica.csv")
)

Importación de Hojas de Cálculo con readxl

A diferencia de readr, el paquete readxl pertenece al ecosistema Tidyverse pero debe cargarse explícitamente con library(readxl). Detecta automáticamente si el archivo es .xls o .xlsx.

Funciones y Parámetros Clave:

  • excel_sheets(): Lista las hojas del libro sin cargar los datos.
  • sheet: Especifica la hoja por nombre ("Ventas") o posición (2).
  • range: Lee un rango exacto de celdas (ej. "B3:F20").
  • na: Define cadenas que representan valores nulos (ej. c("", "N/A", "-")).
  • col_types: Fuerza tipos de columna o omite ("skip").
  • skip: Omite un número de filas iniciales.

Ejemplo de uso con readxl

library(readxl)

# 1. Explorar nombres de hojas
excel_sheets("reporte_2026.xlsx")

# 2. Leer hoja específica por nombre
ventas <- read_excel("reporte_2026.xlsx", sheet = "Ventas")

# 3. Leer rango exacto y personalizar nulos
datos_sub <- read_excel(
  path = "reporte_2026.xlsx",
  sheet = 1,
  range = "B3:F25",
  na = c("", "N/A", "-"),
  col_types = c("text", "numeric", "date", "skip", "numeric")
)

Leer con datos faltantes

En hojas de calculo se escriben con . a veces con espacios en blancos o ambos

# Si los datos faltantes están marcados solo con un punto:
datos <- read_excel("tu_archivo.xlsx", na = ".")

# Recomendado: considerar tanto el punto como las celdas vacías como NA
datos <- read_excel("tu_archivo.xlsx", na = c(".", ""))

Omisión de Filas Iniciales y Encabezados en readxl

Es común encontrar archivos de Excel con títulos, notas o metadatos en las primeras filas antes de la tabla principal. Utiliza el argumento skip para omitirlos:

Parámetros clave:

  • skip = n: Saltea las primeras n filas del archivo.
  • col_names = TRUE: Por defecto, toma la primera fila útil (post-salteo) como nombre de columnas.
  • na = c(".", ""): Combina el salteo de filas con la conversión de caracteres a NA.

Ejemplo con Código:

# 1. Saltear las primeras 4 filas de metadatos/texto
datos <- read_excel("reporte_ventas.xlsx", skip = 4)

# 2. Saltear filas e indicar que el punto "." es dato faltante
datos_limpios <- read_excel(
  path = "reporte_ventas.xlsx",
  sheet = "Ventas_2026",
  skip = 4,
  na = c(".", "")
)

Unir Hojas de Excel con bind_cols()

Pasos del proceso:

  1. Listar hojas: Con excel_sheets().

  2. Cargar por separado: .

  3. Unir en un tibble: Con bind_cols() concatenamos las columnas horizontalmente.

Nota: Ambas hojas deben tener exactamente el mismo número de filas y coincidir ordenadamente.

# 1. Cargar paquetes y listar hojas
ruta_excel <- "reporte_ventas.xlsx"
hojas <- excel_sheets(ruta_excel)

# 2. Cargar cada una por separado (solo 2 hojas)
hoja_1 <- read_excel(path = ruta_excel, sheet = hojas[1])
hoja_2 <- read_excel(path = ruta_excel, sheet = hojas[2])

# 3. Unir en un solo tibble con bind_cols
datos_completos <- bind_cols(hoja_1, hoja_2)

# Visualizar resultado
print(datos_completos)

Combinar Datasets: bind_cols() vs bind_rows()

Diferencias Clave:

  • bind_cols() (Unión Horizontal):
    • Junta columnas de dos o más tablas de lado a lado.
    • Requisito: Mismo número de filas en ambas tablas.
  • bind_rows() (Unión Vertical):
    • Apila registros (filas) uno debajo del otro.
    • Requisito: Nombres de columnas coincidentes (si una tabla no tiene una columna, se rellena con NA).

Pegado de tablas

# 1. Unión Horizontal (Añadir Columnas)
# Junta df1 y df2 a lo ancho
datos_ancho <- bind_cols(df1, df2)

# 2. Unión Vertical (Añadir Filas / Apilar)
# Coloca las filas de df2 debajo de df1
datos_largo <- bind_rows(df1, df2)

# Ejemplo apilando indicando el origen:
datos_apilados <- bind_rows(
  "Hoja 1" = df1, 
  "Hoja 2" = df2, 
  .id = "origen"
)

Bases de datos

Librerías de tidyverse

¿Qué es una Base de Datos?

Una analogía sencilla

Podemos concebirla como gran biblioteca digital centralizada:

  • En lugar de tener archivos Excel desparramados en la computadora, la información está ordenada en tablas.
  • Cada tabla es como una planilla (con columnas para variables y filas para registros).
  • El sistema garantiza que los datos estén protegidos, actualizados y disponibles para muchas personas al mismo tiempo.

💡 La diferencia con Excel

Un archivo .xlsx esta en la computadora y tiene un límite estricto de filas. Una Base de Datos vive en un servidor, maneja millones de datos y no se “cuelga”.

¿Por qué las usamos en Ciencia de Datos?

  • Estructura limpia: Evita datos duplicados o inconsistentes.
  • Velocidad de búsqueda: Utiliza índices (como el índice de un libro) para encontrar un registro en milisegundos entre millones de filas.
  • Fuente única de verdad: Todo el equipo analiza los mismos datos reales sin andar enviándose versiones (datos_final_v2.csv).

Acceso a Bases de Datos en R

¿Por qué conectarse directamente?

  • Autonomía: Evita depender de descargas intermedias de archivos .csv.
  • Eficiencia: Consulta los datos necesarios en tiempo real directamente en el servidor.
  • Estándar: Interactúa mediante SQL usando tus sintaxis habituales de dplyr.

🛠️ Herramientas clave

  • DBI: Interfaz de bajo nivel que gestiona la conexión y ejecuta consultas SQL.
  • dbplyr: Interfaz de alto nivel que traduce código dplyr a consultas SQL.

Paso 4: Manipular los datos con sintaxis dplyr

Se usan los verbos habituales de {dplyr} (filter, group_by, summarise, left_join, mutate). Todo se procesará dentro del motor SQLite.

# Unir las 3 tablas relacionales y calcular el precio medio por tipo de corte
resumen_cortes <- diamantes_db %>% 
  left_join(cortes_db, by = "id_corte") %>% 
  left_join(claridades_db, by = "id_claridad") %>% 
  filter(price > 1000) %>% 
  group_by(corte) %>% 
  summarise(
    cantidad = n(),
    precio_promedio = mean(price, na.rm = TRUE),
    quilates_max = max(carat, na.rm = TRUE)
  ) %>% 
  arrange(desc(precio_promedio))

Paso 6: Traer el resultado final a R con collect()

Hasta este punto, nada se ha descargado a R. Cuando se requiera guardar el resultado procesado como un data.frame local, se ejecut collect():

# Ver la consulta SQL en texto plano que se enviará al servidor
resumen_cortes %>% show_query()
<SQL>
SELECT
  `corte`,
  COUNT(*) AS `cantidad`,
  AVG(`price`) AS `precio_promedio`,
  MAX(`carat`) AS `quilates_max`
FROM (
  SELECT `q01`.*
  FROM (
    SELECT `diamantes`.*, `corte`, `claridad`
    FROM `diamantes`
    LEFT JOIN `cortes`
      ON (`diamantes`.`id_corte` = `cortes`.`id_corte`)
    LEFT JOIN `claridades`
      ON (`diamantes`.`id_claridad` = `claridades`.`id_claridad`)
  ) AS `q01`
  WHERE (`price` > 1000.0)
) AS `q01`
GROUP BY `corte`
ORDER BY `precio_promedio` DESC
